# 生のレスポンシブで出る問題点 (2026-11-01)

Marp の出力に「画面比率に合わせてスライドの枠を作り直す」処理**だけ**を足し、自動縮小 (fit) や CSS の追加・調整をしない状態で、何が起きるかを調べたレポート。試作の経緯は同じディレクトリの `README.md` を参照。

**ビルド・dev には組み込んでいない** (調査用に、ビルド後の HTML のコピーへ差し込んだだけ)。

## 条件

- 差し込んだ処理: `README.md` の試作から fit を除いたもの。仮想キャンバスの短辺を 720px に固定し、`viewBox`・`foreignObject`・`section` の幅と高さを書き換えるだけ
- デッキ: cool-game (39 枚)、Quaver (4 枚)
- 方法: puppeteer + Chrome で全スライドを撮影し、本文のはみ出し量 (下・右) を計測

| 画面               | 画面サイズ | キャンバス |
| ------------------ | ---------- | ---------- |
| 16:9               | 1280×720   | 1280×720   |
| 4:3                | 1024×768   | 960×720    |
| 正方形             | 900×900    | 720×720    |
| タブレット縦 (3:4) | 768×1024   | 720×960    |
| スマホ縦           | 390×844    | 720×1558   |
| スマホ横           | 844×390    | 1558×720   |
| 超横長             | 1720×720   | 1720×720   |

## 結果の概要

「はみ出し」は、本文の下端・右端が section の padding の内側に収まらない量。16:9 でも 2px 以内の誤差が 2 枚あるので、3px 以上を数えている。

| 画面         | 下にはみ出す           | 右にはみ出す | 所見                                        |
| ------------ | ---------------------- | ------------ | ------------------------------------------- |
| 16:9         | 0 枚                   | 0 枚         | 従来と同じ                                  |
| 4:3          | 7 枚 (最大 235px)      | 1 枚         | 本文が切れる                                |
| **正方形**   | **15 枚 (最大 719px)** | 2 枚         | **最悪**。ほぼ 1 画面分切れるスライドもある |
| タブレット縦 | 4 枚 (最大 479px)      | 2 枚         | 一部が切れる                                |
| スマホ縦     | 0 枚                   | 2 枚         | 縦に長いので収まる。広い表だけ右に切れる    |
| スマホ横     | 0 枚                   | 0 枚         | 問題なし                                    |
| 超横長       | 0 枚                   | 0 枚         | 問題なし                                    |

## 問題点 (重い順)

### 1. 4:3 と正方形で本文が黙って切れる

- 下にはみ出したスライド
  - 4:3: Package Manager (+50px)、CI・CD (+143)、数字で見る (+32)、パフォーマンス (+132)、読み取れること (+235)、流石にネイティブのが強いね (+10)、作り込むと辛い (+132)
  - 正方形: 上記に加えて、推しポイント (+40)、環境構築〜初回起動 (+233)、Dev Loop (+53)、パッケージ数 (+481)、それでも軽いのは Web (+138)、Quaver の経緯・かいはつひわ・所感 (+68〜172)。パフォーマンスは +719px
- 原因: 短辺 720px 固定だと、横長でも 16:9 より細い画面では**キャンバスの幅がデザイン時の 1280px より狭くなる** (4:3 で 960px、正方形で 720px)。そのため折り返しが増え、高さ 720px のままなので下が溢れる
- section は `overflow: hidden` なので、**警告も無く切れる**
- 発表で問題になる: 会場のプロジェクターが 4:3 だと、リハーサル (16:9) と違うレイアウトで 7 枚が切れる。固定の 16:9 なら黒帯が出るだけで済む

### 2. 列の多い表が崩れる

- 「数字で見る」(6 列): 正方形・縦長で右に 294px はみ出し、右端の列が切れる
- 「パフォーマンス」: 「何を増やしたか」の列が 1 文字幅まで潰れ、縦書きのように 1 文字ずつ改行される。行が縦に伸び、正方形では表だけで 1 画面を超える
- 表は幅 100% で折り返しに頼るので、列数が多いと縦長では成り立たない

### 3. `<style scoped>` の固定サイズが他の比率で合わない

- 16:9 で溢れないよう手で決めた `font-size` (Quaver の 24px / 27px、cool-game の 29px / 34px) は、16:9 専用の値
- スマホ縦では、画面の下半分が空いているのに小さい文字のまま (Quaver の経緯など)
- 正方形では、その値でもまだ溢れる (Quaver の 3 枚)

### 4. SVG (`<object>`) は縦長で小さくなる

- SVG は横長の比率のまま、枠の中で縮むだけ。スマホ縦のロゴマップは、画面の中央 1/3 程度にしか描かれない
- 「エクスポート」のように `<object>` が 2 つあるスライドは、2 つの段落が残りの高さを等分する (テーマの `p:has(> object) { flex: 1 1 0 }`)。縦長ではロゴが極小のまま、間に大きな空白ができる
- 16:9 でも、SVG が枠を埋める割合は平均 0.80 (最小 0.73)。縦長ではこれより大きく下がる (縦長では計測値が取れず、画像で確認した)

### 5. 中途半端な縦長 (3:4 のタブレット縦) が残る

- スマホ縦ほど縦に長くないので、CI・CD (+75px)、パッケージ数 (+241)、パフォーマンス (+479)、読み取れること (+52) が溢れる
- 後述の「枠の決め方の変更」をしても、ここは残る

### 6. 軽微なもの

- 表紙の henoheno: 縦長では画面の下に寄り、見出しとの重なりが減る (16:9 で見出し面積の 73%、タブレット縦で 25〜53%、スマホ縦で 0%)。崩れてはいない
- Marp 標準の操作パネル (ページ送りのボタン) が、スマホで下端のスライドに重なる。レスポンシブにしなくても起きる

## 問題なかったこと

- 横に長い画面 (スマホ横、超横長) は、16:9 と同じく問題なし
- フッターとヘッダー (左下 / 右下の文字と黒帯) は、どの比率でも正しい位置に出る
- solo / message の中央寄せ、表紙の文字組みは、どの比率でも崩れない
- スマホ縦での文字の大きさ: 本文 36px × (390 / 720) ≈ 19.5px 相当で、読める大きさ
- PDF は変わらない (ビルド後の HTML にだけ差し込むので)

## 比較実験: 枠の決め方を変えると 1 は消える

キャンバスの決め方だけを次のように変えた版 (案 B) で、同じ計測をした。fit や CSS は足していない。

- 16:9 より横長: 高さ 720px 固定 (今までどおり)
- 正方形〜16:9: **幅 1280px 固定** (高さが伸びる)
- 縦長: 幅 720px 固定 (今までどおり)

| 画面         | 短辺 720px 固定            | 案 B                        |
| ------------ | -------------------------- | --------------------------- |
| 4:3          | 960×720、下 7 枚・右 1 枚  | 1280×960、**0 枚**          |
| 正方形       | 720×720、下 15 枚・右 2 枚 | 1280×1280、**0 枚**         |
| タブレット縦 | 720×960、下 4 枚・右 2 枚  | 変わらず (縦長は同じルール) |
| その他       | —                          | 変わらず                    |

- 横長である限り、幅がデザイン時の 1280px を下回らないので、16:9 で収まっていたものは必ず収まる
- 代わりに、正方形付近では文字が小さくなる (900×900 の画面で本文 25px 相当。短辺固定なら 45px 相当)
- 正方形を境に、キャンバスの幅が 1280 → 720 に切り替わるので、**画面の形を連続的に変えると、正方形のところで文字の大きさが急に変わる** (約 1.8 倍)。気になるなら、正方形付近で幅を 1280 から 720 へなめらかに変える

同じ発想の Reveal.js 版 ([aidotse/quarto-pres PR #4](https://github.com/aidotse/quarto-pres/pull/4)) も、16:9〜4:3 は幅固定、それより横長は高さ固定、縦長は幅固定というルールだった。

## 次の一手の候補

上から順に、足すものが少なく効果が大きい。

1. **枠の決め方を案 B にする** (数行の変更)。4:3 と正方形のはみ出しが消え、発表時に 4:3 のプロジェクターでも切れなくなる
2. 残りのはみ出し (タブレット縦の 4 枚、広い表) には、`README.md` の fit (section の font-size 1 つを二分探索) を足す。足すなら、手で入れた `<style scoped>` の font-size は不要になり、比率ごとの過不足 (問題点 3) も一緒に解消する
3. 広い表は、縦長では文字を縮めても読みにくい。縦長では表を横スクロールにするか、割り切る
4. 縦長の SVG は割り切るか、縦長用の SVG を別に用意して出し分ける
